# CS2 KZ Workshop Images

One preview image per [CS2 Workshop KZ map](https://steamcommunity.com/app/730/workshop/), stored in a public GitHub repo and addressable by a predictable raw URL. Other applications fetch map images from here instead of scraping Steam; a daily Sync keeps the store up to date with the Workshop and reports both its scan and its run result to Telegram.

## For consumers: the URL contract

Every image lives in a flat `images/` directory, is a JPEG regardless of the Workshop source format, and is named exactly after the map:

```
https://github.com/jonahbearde/cs2kz-workshop-images/raw/main/images/<name>.jpg
```

- `<name>` is a **Legal map name**: `kz_` followed by lowercase letters, digits, and underscores only (e.g. `kz_ozark`, `kz_152_ladders`). The URL is a pure function of the map name — no extension probing, no lookup step.
- A few images are **hand uploads with non-kz names** (e.g. `de_dust2`). They follow the same URL shape, but never appear in `index.json` and are never touched by the Sync — see [ADR 0005](docs/adr/0005-storable-map-names.md).
- Images are the map's first Workshop preview at **original resolution**, transcoded to JPEG (quality 90, no resize).
- Maps that exist in the Workshop but have no preview image simply have no file; there is nothing to fetch for them.
- [`index.json`](index.json) at the repo root maps each KZ map name to its Workshop metadata — `id` (Workshop item id, Workshop page is `https://steamcommunity.com/sharedfiles/filedetails/?id=<id>`), `previewUrl` (the raw Steam UGC URL), and `timeUpdated` (Unix seconds). It is generated, not hand-edited.

This contract is deliberate and locked in: see [ADR 0001 — All-JPEG, filename-is-map-name public URL contract](docs/adr/0001-jpeg-url-contract.md).

## How it works

- **Enumeration.** A single Steam Workshop search pass (`search_text=kz`, app 730) discovers KZ maps — fast, and probabilistically complete rather than exhaustive, which is fine because the repo is additive-only. See [ADR 0003 — Search-based enumeration](docs/adr/0003-search-based-enumeration.md).
- **Winners.** When several Workshop items share one map name, only the most recently updated one counts; its preview is the one stored.
- **The daily Sync** ([`sync.yml`](.github/workflows/sync.yml)) re-enumerates the Workshop at 01:00 UTC, diffs it against `images/`, sends the scan report to Telegram (always — silence never means "the job died", and failures are reported to the same chat), then downloads every Missing preview and re-downloads every Stale one, sends the run-result message, rebuilds `index.json`, and commits images and index together. Telegram never blocks the run: a send failure is reported through the exit status, not by aborting the work. See [ADR 0002 — index.json is regenerated by the Scan and committed back](docs/adr/0002-actions-generated-index.md).
- **Stored images track the winner.** A stored map whose winner's preview changed is Stale and gets re-downloaded on the next Sync; hand uploads of KZ maps are normalized the same way (non-kz hand uploads are never touched by the Sync; see [ADR 0005](docs/adr/0005-storable-map-names.md)). Consequence: image content at a stable URL can change, so consumers should not cache indefinitely. See [ADR 0004 — The Sync overwrites stored images when the winner's preview changes](docs/adr/0004-sync-overwrites-stale-images.md).
- **Hand upload remains a fallback** for when the Steam API misbehaves (see [Adding an image by hand](#adding-an-image-by-hand)); under normal operation the Sync supplies every image.

## Prerequisites

- [Node.js](https://nodejs.org/) ≥ 24 and [pnpm](https://pnpm.io/) (`packageManager` is pinned in `package.json`), then `pnpm install`.
- A **Steam Web API key** (see below).
- For the Scan/Sync: a **Telegram bot** and a chat id (see below).

### Steam Web API key

1. Log in to Steam in your browser and open <https://steamcommunity.com/dev/apikey>.
2. Agree to the terms. The "Domain Name" field is free-form; any value works for this repo (e.g. `localhost`).
3. Copy the generated key.

**Local runs:** copy [`.env.example`](.env.example) to `.env` (git-ignored) and set `STEAM_API_KEY`. All commands load `.env` automatically.

**GitHub Actions:** add a repository secret named exactly `STEAM_API_KEY` under *Settings → Secrets and variables → Actions → New repository secret*.

### Telegram bot and chat id (from zero)

The Sync reports to a private chat between you and your own bot. No prior Telegram API knowledge needed:

1. **Create the bot.** In Telegram, search for **@BotFather** (the verified one) and start a chat. Send `/newbot`. Pick a display name (anything), then a username that ends in `bot` (e.g. `cs2kz_images_bot`).
2. **Get the token.** BotFather replies with an HTTP API token that looks like `123456789:AA...`. Copy it — this is `TELEGRAM_BOT_TOKEN`. Treat it like a password; anyone holding it controls the bot. If you ever lose it, ask BotFather `/token` in the bot's settings.
3. **Start the private chat.** Open your new bot by its username and press **Start** (or just send it any message, e.g. `hi`). A bot cannot message you until you do this.
4. **Get the chat id.** Open in your browser (replace `<TOKEN>`):

   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```

   In the JSON response, find your message under `result[].message` and read `chat.id` — a plain number for a private chat. That number is `TELEGRAM_CHAT_ID`. If `result` is empty, send the bot another message and reload the page.

**Local runs:** set `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` in `.env`.

**GitHub Actions:** add repository secrets named exactly `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` (same place as the Steam key).

## Commands

All commands are pnpm scripts run from the repo root. `download`, `scan`, `sync`, and `list` need `STEAM_API_KEY`; `scan` and `sync` also need the Telegram secrets.

### `pnpm download` — one-shot seed

Enumerates the Workshop, picks Winners, and downloads every Winner's preview into `images/<name>.jpg`, transcoding to JPEG. Existing files are skipped, so you can interrupt and re-run safely. Titles that aren't Legal map names are rejected outright. Optionally throttle with `pnpm download --limit 10`. Rebuilds `index.json` from what `images/` holds afterwards.

Note: the seed is probabilistically complete (a single search pass misses ~5–17% of KZ maps; see [ADR 0003](docs/adr/0003-search-based-enumeration.md)) — later Scans fill the gap.

### `pnpm list` — enumerate without writing

Lists every currently discovered KZ map name (one per line) to stdout, with progress and counts on stderr. Handy for a quick look at what the search pass sees; writes nothing.

### `pnpm check` — validate hand uploads

Run this after dropping files into `images/` and before pushing. Fully offline (no Steam API):

1. rejects files whose stem is not a **Storable map name** — lowercase letter first, then lowercase letters, digits, and underscores (`^[a-z][a-z0-9_]*$`); every Legal map name qualifies, plus hand-uploaded non-kz names ([ADR 0005](docs/adr/0005-storable-map-names.md)),
2. transcodes non-JPEG files to JPEG in place,
3. rebuilds `index.json` from what `images/` holds — KZ maps without a known Workshop record keep their previous index entry until the next Scan enriches them ([ADR 0002](docs/adr/0002-actions-generated-index.md)); non-kz maps never enter the index.

Exits non-zero if any problem needs fixing by hand.

### `pnpm scan` — the report-only view, locally

What the Sync sees, without the downloads: enumerate → diff against `images/` (with Stale detection) → rebuild `index.json` → send the report to Telegram. The report lists counts (`have / missing / stale / no-preview`), one line per Missing map with its Workshop page link, a Stale section of the same shape, and a separate No-preview section for maps that have no image to download. A report is sent every run; on failure a notification naming the cause goes to the same chat.

### `pnpm sync` — the daily job, locally

What the GitHub Actions workflow runs: the Scan, then downloading every Missing preview and re-downloading every Stale one (each with up to three attempts), then the run-result message (`downloaded / updated / failed`) and the `index.json` rebuild. Telegram never blocks the run, but any download or send failure exits non-zero. On a fatal error a notification naming the cause goes to the same chat.

## Adding an image by hand

Normally unnecessary — the daily Sync supplies every image. Keep this as the fallback for when the Steam API misbehaves and a map can't wait for the next Sync:

1. Open the map's Workshop page and grab the preview image.
2. Save it into `images/` named exactly `<map_name>` — the extension doesn't matter; `pnpm check` transcodes non-JPEGs to JPEG in place.
3. Run `pnpm check`, fix anything it rejects, then commit and push both the image and the updated `index.json`.

The hand upload is a stopgap: once the Sync can see the map again, its Index record gets the winner's metadata, and a later Sync overwrites the image whenever it diverges from the winner's preview ([ADR 0004](docs/adr/0004-sync-overwrites-stale-images.md)).

Non-KZ images (e.g. official `de_` maps) are the one permanent exception: they can only ever arrive by hand, never appear in `index.json`, and the Sync never discovers, overwrites, or re-downloads them ([ADR 0005](docs/adr/0005-storable-map-names.md)).

## Development

- `pnpm typecheck` — TypeScript, no emit.
- `pnpm test` — Vitest suite; fully offline (fixtures across the Steam and filesystem seams).

CI ([`ci.yml`](.github/workflows/ci.yml)) runs both on every push to `main` and on pull requests.
